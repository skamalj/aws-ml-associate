# AWS Certified Machine Learning Engineer - Associate (MLA-C02) practice notebooks

Hands-on Jupyter notebooks that cover every skill in the
[MLA-C02 exam guide](https://docs.aws.amazon.com/aws-certification/latest/machine-learning-engineer-associate-02/machine-learning-engineer-associate-02.html),
built around one continuous story.

> **Status:** the notebooks were written and statically checked (Python syntax and boto3 API
> parameters), but they have **not been executed against a real AWS account**. Expect to fix the
> odd cell, especially in the newest services (Bedrock AgentCore, S3 Vectors, evaluations).

## The story: SafeDrive Insurance

You are the ML engineer at SafeDrive, a fictional motor insurer. Across the notebooks you build two systems:

1. **Claim fraud model** - traditional ML (XGBoost on Amazon SageMaker AI).
2. **Claims assistant** - generative AI (RAG over policy documents, a Bedrock agent with tools, guardrails).

Then you deploy, automate, monitor, cost-optimize and secure both. The dataset is synthetic and is
generated by the setup notebook (fixed seed, no downloads):

| File | What it is | Used for |
|---|---|---|
| `policies.csv` | 5,000 policyholders | joins, Feature Store, bias |
| `claims.csv` | 20,000 claims, `is_fraud` label (~5%) | the fraud model |
| `claims_v2.parquet` | a later month with nulls, duplicates, outliers and drift | data quality, drift |
| `telematics_stream.jsonl` | driving events | Kinesis and Lambda streaming |
| `policy_docs/*.md` (+ metadata) | 5 policy documents | chunking, embeddings, Knowledge Base |
| `adjuster_notes.jsonl` | claim notes with fake PII | PII redaction, text processing |
| `finetune_qa.jsonl`, `qa_eval.jsonl` | prompt/answer pairs, golden Q&A | fine-tuning data, evaluation |
| `images/` | car-damage drawings and a claim form | Rekognition, Textract, image embeddings |
| `audio/call_sample.mp3` | a short call (made with Polly) | Transcribe |

## How each notebook is organised

1. **Header** - story chapter, task statement and the skill IDs covered.
2. **Key points for the exam** - a few bullets and "choose X when..." tables.
3. **Setup + catch-up cell** - loads shared config and builds anything an earlier notebook would have made.
4. **One section per skill** - the heading carries the skill ID (search for `2.2.3`), a short note, then small code cells with one activity each.
5. **Exam traps** and a **5-question quiz** (answers are collapsed).
6. **Cleanup** - deletes what the notebook created, except things later notebooks need.

## Getting started

**Prerequisites**

- An AWS **sandbox** account and credentials that already work (`aws sts get-caller-identity`).
  The identity needs to create S3 buckets, IAM roles and the services used (an admin-like user is simplest).
- A region with Amazon Bedrock, S3 Vectors and AgentCore, for example `us-east-1` or `us-west-2`.
- Python 3.10+ and Jupyter (local, or SageMaker Studio / JupyterLab).
- The **AWS CLI** (a few cells in 3.2a call `aws ...`). Docker is optional (only one 🔒 section uses it).
- Access to the Bedrock models used: Amazon Nova Micro/Lite/Pro, Amazon Titan Text Embeddings V2,
  Titan Multimodal Embeddings. The setup notebook tests this.

**Steps**

```bash
git clone <this repo> && cd aws-ml-associate
```

```bash
pip install -r requirements.txt
```

```bash
export AWS_REGION=us-east-1
```

```bash
jupyter lab
```

Then run `00_setup/00_environment_and_data.ipynb` top to bottom, and continue with 1.1.

**Order.** The notebooks follow the story, so going in order (1.1 → 4.3b) is best. You can also
jump to any notebook: its catch-up cell (`C.ensure_...`) builds the missing pieces, which can take
a few minutes the first time (for example, training the fraud model).

**Configuration** (all optional, environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `AWS_REGION` | CLI profile region, else `us-east-1` | Region for everything |
| `SAFEDRIVE_BUCKET` | `safedrive-mla-<account>-<region>` | Practice bucket |
| `SAFEDRIVE_ROLE_ARN` | `safedrive-practice-role` | Service role used by all notebooks |
| `SAFEDRIVE_TEXT_MODEL`, `_SMALL_MODEL`, `_LARGE_MODEL` | Nova Lite / Micro / Pro inference profiles | Bedrock text models |
| `SAFEDRIVE_EMBED_MODEL` | `amazon.titan-embed-text-v2:0` | Embedding model |
| `RUN_EXPENSIVE` | `false` | Set to `true` to run 🔒 cells |

**Time.** Most notebooks take 30-60 minutes to run end to end, mainly waiting for jobs and endpoints.

## Cost and safety

- Most cells use serverless or small resources (`ml.m5.large`, short jobs), but **this is not free**.
  Budget a few US dollars per notebook if you clean up, and never leave endpoints running.
- 🔒 cells are skipped unless you set `U.RUN_EXPENSIVE = True`. They cover things like Bedrock
  fine-tuning, Provisioned Throughput, GPU endpoints and OpenSearch Serverless, or need a manual
  prerequisite (a labeling workforce, Docker).
- Notebook 1.1b runs an **OpenSearch Serverless collection** by default (about USD 0.25-0.50 per hour
  until its cleanup section deletes it).
- Run the **Cleanup** section at the end of each notebook, and `99_cleanup/99_teardown.ipynb` when
  you are completely done.
- Everything is tagged `project=mla-c02-practice` and named `safedrive-*`, so leftovers are easy to find.
- `safedrive-practice-role` has **broad permissions on purpose** so that practice is not blocked.
  Use a sandbox account, and see notebook 4.3a for the least-privilege version.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| `AccessDeniedException` on a Bedrock call | No access to that model in this region; change the `SAFEDRIVE_*_MODEL` variable or region |
| "Role cannot be assumed" right after setup | IAM is eventually consistent; wait 10 seconds and re-run |
| `ResourceLimitExceeded` on a SageMaker job or endpoint | Service quota for that instance type is 0; request an increase or change the instance type |
| A cell fails on an unknown parameter | The service API changed; run `python tools/nbcheck.py <notebook>` with your boto3 version to locate it |
| A catch-up cell takes long | It is building an earlier step (training job, Knowledge Base); let it finish once |

## Cells most likely to need a fix

The notebooks were not run against AWS, so treat these areas as "check first if something fails":

| Area | Notebooks | Why |
|---|---|---|
| Bedrock AgentCore (Runtime, Gateway, Memory, Observability) | 3.1b, 3.2b, 4.1b | New and fast-changing APIs; region availability |
| Bedrock evaluation jobs, batch inference, fine-tuning (mostly 🔒) | 2.2b, 2.3b, 3.2b, 4.1b, 4.2 | Request formats differ per model; some model IDs are region-limited |
| Reranking, prompt caching, prompt routing | 3.2b, 4.2 | Depend on model and region support (wrapped in try/except) |
| Glue Data Quality rules, DataBrew recipe and profile output | 1.2a, 1.3 | Rule syntax and output field names written from the documentation |
| Clarify and Model Monitor result parsing | 1.3, 2.3a, 4.1a | Output JSON paths written from the documentation |
| Canary deployment and auto scaling | 3.3a, 3.2a | Need instance quota (up to 4 x `ml.m5.large` for the canary) |
| Spot and 2-instance training | 2.2a | New accounts may have zero quota (handled, the job is skipped) |
| Results on the synthetic images | 1.2b, 2.1 | Rekognition, Textract queries and image embeddings may give generic output on drawings |

Timing matters in a few places (Firehose delivery, Feature Store offline store, CloudTrail events, Cost
Explorer tags): if a "wait" cell finds nothing, wait a few minutes and re-run it, as the notebook text says.
